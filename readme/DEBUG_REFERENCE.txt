结论
--------------------------------------------------------------------------------

1. 当前没有可信的物理抓取、物理抬升、preinsert、insert 或 release 结果。
2. 当前工程栈包含运行时资产审计、26D 控制权验证、目标过滤接触、reset-only write 约束、向量环境、候选缓存、严格 evaluator、逐帧 trace 和视频对齐。
3. 仅能够严格核对的正式 CEM/Gate/RC2 已执行至少 1,394 次 fresh reset：CEM 1,280、Plug2 v1 20、Plug2 forensic 80、五对象 v3 Plug2 12、Frame RC2 2。这还没有计算早期 45 个 Screw1 baseline 目录和 contact-adaptive calibration/trial，因为它们没有一个可信的总 reset 计数。
4. 失败不是一个单一算法结论。不同阶段分别暴露了 runtime wrist、接触归因、候选几何、strict M0、厘米级 target residual、RC2 reset penetration 等问题。
5. 后续开发不应原样重跑旧 CEM/旧 Screw1 seed；应从运行时可验证、低力、粗粒度接触目标开始，优先 Rod/Backrest，并允许有限的 diagnostic physics 绕开 strict M0 开发入口。

项目概览
--------------------------------------------------------------------------------

当前成果是 Wuji 五指手物理抓取研究基础设施和可复现失败证据，不是成功装配视频。系统已经验证腕部和 20 个手指关节的控制链，建立对象级几何/spec、候选生成、接触传感、物理 Gate、视频和 trace 对齐，并执行 1,280 个 Screw1 搜索样本、100 个 Plug2 Gate resets、五对象 M0 和两代 Frame 路线。已知瓶颈包括运行时候选接触几何、过严的离线物理入口以及 Frame reset 碰撞。

主要工作阶段：

- 最初先把统一五对象 workcell、active object state、26D action mapping、target-filtered contact sensor 和 reset lifecycle 查清楚，证明 contact API 和 wrist/hand 控制链本身可以工作。
- 随后围绕 Screw1 做了 45 个 baseline/debug 目录，逐步排除了无手稳定性、action authority、wrist target propagation、seed replay、contact handoff 和 dual regulator 的若干实现问题。最终仍没有稳定双指接触。
- 做了 40 个 signed joint probes，得到了有效 30x20 morphology effect matrix；又尝试 object-relative 6x8 local Jacobian。矩阵本身 rank 6，但 restore repeatability 不合格，所以没有把不可靠模型交给主控制器。
- 搭建了 128-env near-grasp 环境。vector smoke 从 articulation/device/mass/quaternion bug 逐步修到 220 steps 通过；正式 5-generation CEM 完成 1,280 candidates，但只有两个目标接触，而且都超过 5 N，零 dual contact、零 close、零 lift。
- 转向 privileged geometry：Plug2 v1 跑 20 resets，forensic v2 跑 80 resets。后者证明实际 tip-to-target residual 是 20-41 mm，而 Pinocchio/Isaac FK 误差很小，因此不能继续把问题归因于简单 joint-order/FK 错误。
- 扩展到五对象后，Rod/Backrest/Frame 大部分 Stage A 可达，但 strict M0 全是 0，所以根本没有进入物理；只有 Plug2 的一个 strict candidate 进入 12 resets，仍失败。这说明 strict M0 适合验收，却不适合做唯一开发入口。
- Frame RC1 生成 12 个 cage candidates，但 scene query 无法验证中央孔/杆件，物理 reset 为 0。RC2 放弃搜索，固定三指 fork；baseline 第二个数值帧约 119.54 N，说明 reset 已碰撞；-5 mm correction 后手-Frame 力归零，但 Frame 三帧移动 19.18 mm，exact collider 又没有 actor-pair 证据。
- 当前产物是经过系统测量并定位到层级的失败证据和可继续使用的工程接口，不是物理成功。

已实现工程能力
--------------------------------------------------------------------------------

A. 运行时和控制权

- 建立 floating Wuji 26D action 路径：6D wrist + 20D hand。
- 单独 wrist smoke 在无家具/无桌/无地面场景中，PD fix on/off 各 5/5 waypoints 通过，证明 wrist position target 可以传播；这不等于在家具场景中路径可行。
- 20 joints x positive/negative = 40 probes，形成 30x20 effect matrix，crosstalk max 0.07784、mean 0.04293。
- reset-only object/root write 和 post-reset write audit 被加入 near-grasp、Gate 和 Frame 环境。

B. 接触真实性

- 五指 target-filtered force matrix、unfiltered force、Table/ground filter、actor-pair callback 和 unresolved residual 被分开记录。
- 证明 cube-to-cube reference contact 和 sensor structure可用；同时发现 GPU Table/ground filter 和部分 actor-pair callback 并不可靠。
- 明确禁止把 unfiltered residual 推断为某个具体碰撞体，也不把距离当接触。

C. 搜索、候选和验收

- 完成 128-env、169D observation 的 dedicated Screw1 environment，vector smoke 最终达到 220 steps finite observations。
- 完成 mixed CEM、candidate-level strict evaluation、incremental metrics 和 handoff replay。
- 建立五对象 ObjectGraspSpec、allowed regions/groups/modes、runtime collision mesh audit、friction-cone gravity wrench、staged IK、immutable candidate cache。
- 建立 Gate A/B/C 和 Frame A/B/C/NONE milestone evaluator；当前代码已修正“generic Gate C 只到 lift 却叫 full route”的语义。

D. 可复现失败证据

- Plug2 forensic 保存了 80 reset traces、首帧、contact attribution、Isaac/Pinocchio FK 对照。
- CEM handoff 保存 candidate 373 no-contact 和 candidate 33 hard-abort 的同步失败视频。
- Frame RC2 保存 baseline debug video；但要注意它只匹配 attempt_0，不匹配最终 correction_1 数值结果。

失败过程中沉淀出的高价值代码资产
--------------------------------------------------------------------------------

当前可复用主线大约有 16,060 行：near-grasp core 3,823 行、grasp synthesis 3,210 行、Frame physical delivery 2,847 行、六个关键 runner 4,926 行、四份核心纯测试 1,254 行。另有约 13,341 行早期 control/diagnostic 模块；它们不应继续作为默认算法，但保存了运行时知识。

行数本身不证明质量。真正有价值的是以下代码已经形成清楚的输入/输出、fail-closed 安全边界、机器可读证据和纯测试。这些模块可以继续使用，即使产生它们的某次抓取实验失败。

1. Dedicated vectorized physics environment

核心文件：
- `near_grasp/near_grasp_physics_env.py`
- `near_grasp/observation.py`
- `near_grasp/grasp_program.py`

已经解决的问题：
- 将五对象 modulo/legacy backend 之外的 Screw1 专用物理场景独立出来。
- 建立 128-env、169D named observation、device-local phase state、reset-only writes、force guards和finite-observation smoke。
- 把 program/template、wrist residual、hand prior、接触历史和物体相对变换放在一个可批处理环境中。

为什么值得复用：
- v3-v9 vector smoke真实经历并修复 articulation root、CPU/CUDA index、mass backend、quaternion broadcast和scalar synchronization问题；最终不是“理论上支持并行”，而是 128 env/220 steps runtime PASS。
- 新算法可以替换 program/controller，而不必重写 scene、observation、reset、sensor 和 evaluator plumbing。

深刻教训：
- 把 `num_envs` 改大不是向量化。每个 quaternion constant、index tensor、reset write和phase transition都必须具有 batch semantics。
- vector smoke必须覆盖多次reset和足够长时序；1-step PASS不能证明episode lifecycle正确。

2. Search 与 strict physical truth 分离

核心文件：
- `near_grasp/evaluator.py`
- `grasp_synthesis/grasp_energy.py`
- `grasp_synthesis/physics_validator.py`
- `near_grasp/cem.py`

已经解决的问题：
- SearchMetrics、lexicographic CEM ranking和StrictPhysicalEvaluator各自负责不同语义。
- target-filtered contact、stable close、lift、table support、drift、force、root writes全部由独立evaluator判断，不读取reward_total。
- no-contact与safe-contact排序错误已经被测试锁住；generic Gate C也不再冒充assembly full route。

为什么值得复用：
- 后续可以大胆修改search shaping，而不用放松最终物理标准。
- anti-reward-hacking和honesty fields已经进入数据结构，可直接复用现有成功定义。

深刻教训：
- 开发指标和验收指标必须分离，但不能彼此失联。旧CEM的strict evaluator是诚实的，search ranking却把zero-contact elite保留下来，导致算力被错误目标吸收。
- 成功字段命名也是控制系统的一部分；一个错误的`full_route_success`会污染报告、视频和后续决策。

3. Prior adapter 和低维 program 接口

6. Staged IK、collision continuation 与 wrench feasibility

核心文件：
- `grasp_synthesis/wuji_ik.py`
- `grasp_synthesis/grasp_energy.py`

已经解决的问题：
- Pinocchio 26DOF model、runtime joint order、tip frames、point Jacobian、DLS和least-squares fallback集中在一个kinematic model。
- HPP-FCL检查self/hand-object/table collision，支持closed/pregrasp/standoff/path阶段。
- friction-cone LP检查gravity wrench；不再用两列SVD冒充force closure。
- `GraspCandidate`保存per-tip residual、support vertex、penetration pairs、path flags和Gate eligibility。

为什么值得复用：
- 这是可替换optimizer的完整研究骨架；可更换seed/contact topology，同时保留collision、wrench、serialization和Gate loader。

深刻教训：
- Stage A高reachability与strict M0=0说明优化目标之间存在竞争；把1 mm residual、collision、path和wrench一次性作为唯一入口会让物理层得不到信息。
- offline FK一致不等于runtime contact target一致；support vertex、tip frame、object pose和cooked geometry必须在第一物理帧交叉验证。

7. Object-space contact controller 与重新接触

核心文件：
- `grasp_synthesis/contact_controller.py`
- `precontact_fingertip_controller.py`
- `dual_contact_regulator.py`

已经解决的问题：
- 每个active finger使用独立point Jacobian、DLS、force normal feedback、joint cap和wrist cap。
- 0.05 N latch、0.035 N keep、连续三步失联释放并允许reacquire，替代永久freeze。
- local Jacobian记录singular values、condition、projection residual、restore error、lag和crosstalk。

为什么值得复用：
- 虽然Screw1 local Jacobian因restore gate未进入主线，但代码准确区分了“矩阵结构可控”和“当前endpoint测量不可重复”。
- 控制器可用于Rod/Backrest runtime target，不需要回到blind polarity search。

深刻教训：
- 一个数学上rank 6的Jacobian仍可能在实际actuator settle/restore下不可用。
- 接触不是一次性事件；controller必须允许loss、reacquisition和finger-independent progression。

工程资产与限制
--------------------------------------------------------------------------------

已实现的可复用资产包括128环境物理执行器、五对象几何/spec、Pinocchio/HPP-FCL候选求解、force-wrench检查、独立strict evaluator、immutable cache、逐帧contact forensic、Frame Stage 4状态机和纯回归测试。实验反例覆盖设备广播、reset写入、厘米级target residual、空actor-pair、strict M0过严和碰撞帧校准。

这些能力解决可运行、可测量、可复现和不误报的问题，但不会自动产生可行抓法。物理里程碑仍然全部为false。剩余任务是基于真实runtime geometry定义link/support surface、collision-free approach和低力多指承重策略。

待实现任务：

1. 优先 Rod 或 Backrest，而不是继续从 Screw1/Plug2 开始。它们的 Stage A reachability 已经很高，尺寸也更适合 Wuji 指间距。
2. 给 strict M0 旁边增加“diagnostic-only physics gate”：允许 collision-safe、厘米以下但未到 1 mm 的候选做一次低力 contact acquisition；仍不得算成功。
3. 第一帧直接从 Isaac runtime tip/link collision vertices 和 object mesh 反算 contact target，不再只信离线 support vertex。
4. 先证明两个不同 finger 对目标对象有 actor-pair + filtered-force 共同证据，再做 close/lift。
5. 对 Frame 先构造 collision-free reset measurement；不要从 119 N 的碰撞帧继续推导 offset。
6. 修复或替代 actor-pair instrumentation 后，再对 correction_1 的 Frame jump 定具体碰撞体。
7. 只有 safe multi-contact hold 可复现时，才讨论 residual RL；旧 14D latent/speed/hold PPO 没有直接接触控制权，不应直接重启。

不要再原样重复什么
--------------------------------------------------------------------------------

1. 不要原样重跑 5-generation Screw1 CEM。
   已有证据：debug_runs/screw1_near_grasp_cem_5gen_vectorized/。
   1,280 candidates 中仅 2 个 target contact，都是 6.31 N/16.50 N hard abort；旧 ranking 会保留 no-contact low-motion elites。除非先改变接触目标、template 或 ranking，不增加信息量。

重要的解释边界
--------------------------------------------------------------------------------

- 74 个目录不等于 74 个算法，也不等于 74 次完整物理抓取。很多是一次实现错误的 smoke、host health、summary plumbing或单轴控制验证。
- `result_class` 是历史代码当时的输出，不一定是可靠物理语义；必须与 phase、force、trial、video和 honesty fields一起看。
- “CONTACT_ACQUISITION_INCOMPLETE”说明当前执行器没拿到接触，不等于物体不可抓。
- “KINEMATIC_GRASP_BLOCKER_PROVEN”是当时 runner/seed/path上的 blocker，不是全局机械不可行证明。
- actor-pair没有证据时，不能确认某个具体非目标碰撞体。
- current debug videos都是失败或 assisted/oracle evidence；没有一段可命名为 physical full-route success。
